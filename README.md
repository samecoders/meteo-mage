# 메테오 법사 (Meteor Mage)

넓은 평원에서 수만 마리로 불어나는 몹 물결을 끌고 다니며 마력을 모으고, 몹이 **올 자리**를 예상해 메테오를 떨어뜨려
한 번에 수천 마리를 날려 버리는 세로 화면 생존 액션 웹게임. 순수 JavaScript(ES 모듈) + WebGL 인스턴싱, 빌드 도구·외부 라이브러리 없음.

---

## 1. 로컬 실행

ES 모듈은 `file://` 로 열 수 없으므로 정적 서버가 필요합니다. Python 3 이 있으면:

```bash
python tools/serve.py
```

브라우저에서 <http://localhost:8080> 을 엽니다. (`tools/serve.py` 는 캐시를 끈 서버라 파일을 고치면 새로고침만으로 바로 반영됩니다.)

같은 Wi-Fi 의 폰에서 시험하려면:

```bash
python tools/serve.py 8080 --lan
```

폰 브라우저에서 `http://<PC의 IP>:8080` 으로 접속합니다. (PC 방화벽에서 8080 포트 허용 필요)

Node 가 있다면 `npx serve .` 같은 다른 정적 서버도 됩니다.

## 2. 무료 배포

정적 파일뿐이라 폴더 전체를 그대로 올리면 됩니다. 특수 서버 헤더(SharedArrayBuffer 등)는 쓰지 않습니다.

**GitHub Pages**
1. 이 폴더를 GitHub 저장소에 올립니다.
2. 저장소 Settings → Pages → Source: `Deploy from a branch`, Branch: `main` / `(root)` → Save.
3. 1~2분 뒤 `https://<아이디>.github.io/<저장소>/` 에서 실행됩니다.

**Cloudflare Pages**
1. dash.cloudflare.com → Workers & Pages → Create → Pages → 저장소 연결(또는 폴더 직접 업로드).
2. Framework preset: `None`, Build command: 비움, Output directory: `/`.
3. 배포 후 `https://<프로젝트>.pages.dev` 에서 실행됩니다.

폰에서 공유 메뉴 → "홈 화면에 추가" 하면 `manifest.webmanifest`(display: fullscreen, orientation: portrait) 덕분에 주소창 없이 실행됩니다.

## 3. Supabase 랭킹 설정 (선택)

설정하지 않으면 랭킹 화면에 **내 기기 기록**만 나오고 게임은 정상 동작합니다.

1. <https://supabase.com> 에서 무료 프로젝트를 만듭니다.
2. 대시보드 → **SQL Editor** → `supabase/schema.sql` 내용을 통째로 붙여 넣고 **Run**.
   - 테이블 `scores(id, nickname, country, kills bigint, survive_sec, level, max_combo, meteor_skin, device_id, created_at)` + 인덱스
   - RLS 켜고 정책 없음 → 클라이언트는 테이블에 직접 접근 불가
   - RPC 함수 3개만 공개: `submit_score`, `get_top`, `get_my_rank`
   - 서버 쪽 부정 방지: 생존 시간으로 가능한 최대 킬 수 초과, 레벨의 최대 반경으로 불가능한 한방 콤보, 기기당 분당 3회 초과, 닉네임 길이·문자 검사 → 거부
3. 대시보드 → **Project Settings → API** 에서 `Project URL` 과 `anon public` 키를 복사해 `js/config.js` 에 넣습니다.

```js
ranking: {
  supabaseUrl: 'https://abcd1234.supabase.co',
  supabaseAnonKey: 'eyJhbGciOi...',
},
```

- anon 키는 공개되어도 되는 키입니다(RLS + RPC 검사로 보호).
- `js/config.js` 의 스폰·메테오 수치를 크게 바꾸면 `supabase/schema.sql` 상단의 한도 함수(`max_kills_possible`, `max_combo_possible`)도 맞춰 주세요.
- 다른 백엔드로 바꾸려면 `js/ranking.js` 의 `submitScore()` 와 `fetchTop()` 두 함수만 바꾸면 됩니다.
- 수집 정보: 닉네임, 국가, 기록, 무작위 기기 ID(UUID) 뿐입니다.

## 4. 벤치마크와 디버그

| 주소 | 동작 |
|---|---|
| `?bench=60000` | 몹 60,000마리를 즉시 배치, 법사가 자동으로 원을 그리며 돎(무적), 10초마다 자동 메테오. 디버그 표시 자동. 60초 뒤 결과 한 줄(평균 fps, 틱당 시뮬 ms, 50ms 넘는 프레임 수)을 화면과 콘솔에 표시 |
| `?bench=100000` | 숫자를 바꿔 다른 수로 시험 |
| `?debug=1` | 화면 왼쪽 위에 fps, 몹 수, 시뮬레이션 ms/틱, 렌더 ms, 화질 단계, 내부 해상도, 그린 몹 수 표시 |

### 폰에서 확인할 항목
1. `?bench=60000` 을 1분 이상 켜 두고 → 결과 줄의 `avg fps`(목표 60, 최소 30), `sim ms/tick`(목표 8ms 이하), `frames>50ms`(GC 멈춤, 0~1이 정상).
2. 메테오가 떨어지는 10초마다 프레임이 눈에 띄게 떨어지지 않는지(짧은 멈춤은 의도된 히트스톱).
3. 일반 게임에서 한 손가락 이동 중 다른 손가락 탭/대시가 바로 되는지.
4. 세로·가로 회전, 노치 폰에서 검은 띠·잘림 없이 꽉 차는지. 픽셀이 흐리지 않고 또렷한지.
5. 설정에서 언어를 바꾸면 모든 문구가 즉시 바뀌는지.

### 이 환경에서 잰 값 (참고)
개발 PC(숨겨진 브라우저 창이라 CPU가 상당히 느리게 잡힘 — 60k 원소에 `sqrt` 한 번 도는 단순 루프가 0.5ms) 기준:

| 항목 | 값 |
|---|---|
| `?bench=60000` 시작 직후 | 60 fps, 시뮬 1.5ms/틱, 렌더 0.5ms |
| `?bench=60000` 10초 뒤(6만 마리가 좁은 원에 빽빽 — 최악 조건) | 시뮬 5~6.6ms/틱 (격자 1.2ms + 이동 3.8ms 등), 화면 안 몹 23,000마리 배치 채우기 1.2ms/프레임 |
| 일반 게임 8분(5만 마리) | 시뮬 약 4.5ms/틱 |

시뮬레이션은 30틱/초라 60fps에서 두 프레임에 한 번 돌기 때문에 프레임당 평균 부담은 그 절반입니다.
중급 폰(갤럭시 A5x, 아이폰 12)은 위 PC 환경보다 대체로 빠르거나 비슷할 것으로 보지만 **실기기 측정이 필요합니다**. `?bench=60000` 결과 줄을 알려 주시면 조정하겠습니다.

### 8ms를 넘는 경우: Web Worker 분리안
- 비용 대부분은 `js/sim/mobs.js` 의 `moveMobs`(몹마다 법사 방향 + 밀도 압력 쌍선형 보간)와 `js/sim/grid.js` 의 격자 재구성입니다.
- 분리 방법: `game.js` 의 `tick()` 을 워커로 옮기고, 메인 스레드는 입력(법사 위치·탭)만 보냅니다. 워커는 매 틱 몹 위치를 **전달 가능한(transferable) ArrayBuffer** 두 개(핑퐁)에 담아 `postMessage(buf, [buf])` 로 넘기고, 메인은 그리기만 한 뒤 버퍼를 돌려줍니다. 복사 없이 소유권만 오가므로 SharedArrayBuffer(특수 헤더 필요) 없이 정적 호스팅에서 동작합니다.
- 법사 이동은 이미 프레임마다 메인 스레드에서 하므로 조작감은 그대로이고, 판정은 워커 틱에서 하므로 공정성도 같습니다.

## 7. 성능 설계 요약
- 몹은 객체 없이 최대 수만큼 미리 할당한 타입 배열(SoA). 살아 있는 몹은 앞쪽에 촘촘히, 죽으면 마지막 몹과 자리 바꾸기.
- 10틱마다 몹 배열을 격자 칸 순서로 재배치해 캐시 효율을 높임.
- 법사 중심 160×160 칸(칸 32단위) 격자를 매 틱 카운팅 정렬로 재구성. 충돌·메테오 피해·마력용 주변 몹 수·쉴드 밀치기·화염 지대는 모두 해당 칸만 조회.
- 분리 처리는 몹끼리 비교하지 않고 칸 밀도²의 기울기(덜 붐빈 쪽)로 밀어내기. 쌍선형 보간해 칸 경계가 보이지 않게 하고, 짝/홀 몹을 번갈아 계산해 비용 절반.
- 게임 로직 30틱/초 고정, 한 프레임 최대 3틱, 더 밀리면 게임 시간을 늦춤. 느린 기기에서도 몹 수·스폰·판정은 그대로(시드 고정 난수), 그리는 품질만 낮춤.
- 몹 전체를 하나의 인스턴스 버퍼(12바이트/마리)로 드로우 1회. 화면 밖 몹 제외. 걷기는 셰이더에서 위상별 1픽셀 통통 튀기.
- 짧은 변 360px(줌 아웃 시 480·600) 내부 프레임버퍼에 그린 뒤 nearest 확대. 텍스처 NEAREST, 밉맵 없음, 좌표는 셰이더에서 정수 픽셀로 반올림.
- 게임 중 매 프레임 새 배열·객체를 만들지 않음(이펙트도 고정 풀).

## 8. 사양에 없어서 정한 것
- **대시 입력**: "누르고 있는 동안 끝 지점 미리보기"와 "누르면 돌진"을 함께 만족시키려고 *누르면 미리보기, 떼면 돌진*으로 했습니다(짧게 누르면 사실상 즉시). Shift 도 같습니다.
- **화면 비율 처리**: 짧은 변을 정확히 360 내부 픽셀(월드 720)로 고정하고 최근접 확대합니다. 배율이 정수가 아닌 기기(예: 아이폰 12는 3.25배)는 픽셀 폭이 3·4 장치 픽셀로 섞이지만 고밀도 화면이라 눈에 띄지 않습니다.
- **줌 아웃**: 메테오 범위로 정해지는 단계(360/480/600)를 향해 내부 해상도를 1픽셀씩 천천히 바꿔 부드럽게 줄입니다. 스프라이트는 언제나 1텍셀=1픽셀입니다. 스폰 반경도 줌 단계에 비례(기기와 무관).
- **멀리 있는 몹 판단 기준**: "화면 범위의 2배"는 기기마다 달라 공정성이 깨지므로 고정 거리(`mobs.farSkip` 1500, 재배치는 스폰 반경×1.75)로 했습니다.
- **법사 이동은 프레임마다**(사양대로), 몹 접촉 판정은 틱에서 그 순간 법사 위치로 합니다.
- **최빈색 축소**: AI 이미지의 색 노이즈 때문에 원본 픽셀을 먼저 팔레트로 맞춘 뒤 칸마다 가장 많은 팔레트 색을 고릅니다.
- **마력**: 기본 1.6/초 + min(8, 1.1×log2(1+반경 230 안 몹 수))/초 + 구슬. 구슬은 폭발 1회에 4×4칸 블록 단위로 묶고 총량 상한 22.
- **경험치**: Lv1→2 100, 레벨마다 ×2. 자동 플레이 시뮬레이션(무적 봇, 8분)에서 평균 약 44초에 1번 레벨업.
- **골드**: 10킬당 1 × 한방 배율, 한방 콤보 보너스(100/500/1000/3000/8000킬), 보스 300.
- **가격**: 쉴드 100부터 ×2, 대시+ 150부터 ×2(5단계). 메테오 모양: 얼음 2,000 / 독 5,000 / 번개 10,000 / 암흑 20,000 / 황금 40,000.
- **보스**: 2분마다, 체력 60부터 등장마다 ×1.35(메테오 5발 정도), 처치 골드 300.
- **화염 지대**: 칸 중심이 원 안인 칸의 몹에게 초당 위력×0.9 피해, 3초.
- **아슬아슬 보너스 범위**: 폭발 반경 바깥 45단위 이내.
- **쉴드가 깨진 뒤 1.5초 무적**은 메테오 폭발도 막습니다(무적이므로). 대시 무적은 몹 접촉만 막습니다.
- **첫 판 안내**는 15초 동안 4단계(이동 → 마력 → 탭 → 대시)로 그림과 화살표를 보여 주고, 끝까지 본 뒤에만 다시 나오지 않습니다.
- **국가 이름**은 `Intl.DisplayNames` 로 현재 언어에 맞춰 표시하므로 번역 파일에 넣지 않았습니다.
- **랭킹 목록**은 기기별 최고 기록 1개씩 상위 100명입니다.
- 서비스 워커(오프라인 캐시)는 넣지 않았습니다. 개발 중 오래된 파일이 남는 문제를 피하려는 것이며, 홈 화면 추가와 전체 화면 실행은 manifest 만으로 됩니다.

## 10. 2차 업그레이드 (2026-11-19, 새 이미지 반영)

### 그림
- **원래 해상도 그대로 사용**: 가로·세로 128px 이하 이미지는 이미 도트로 찍힌 그림으로 보고 줄이지 않습니다(투명 테두리 잘라내기·반투명 제거만). 팔레트 강제도 하지 않습니다(`pixel.snapNative: false`). 이전 규칙대로 12~20px로 줄이면 새 그림이 뭉개지기 때문입니다. 큰 AI 원본은 예전처럼 `size`로 변환합니다. `tools/pixelize.html`도 같은 규칙을 씁니다.
- 지면: `ground` 위에 `ground_dirt`가 저주파 노이즈로 군데군데 섞입니다(셰이더, 경계는 2픽셀 단위로 거칠게). 흙 비율은 `decor.dirtThreshold`.
- 평원 장식: 나무·바위·덤불·폐허가 200단위 칸마다 해시로 정해진 자리에 놓입니다(그림만, 판정 없음).
- 폭발은 `fx_explosion`을 반경에 맞는 **정수 배율**로 띄우고, 보스 타격 `fx_hit`, 레벨업 `fx_levelup`, 폭발에서 튀어 오르는 동전 `item_coin`을 씁니다. 마력 구슬은 `item_expgem` 보석으로 바뀌었습니다.
- UI: `ui_frame`(9-slice)을 패널·버튼 테두리로, `ui_button`/`ui_button_pressed`를 주요 버튼으로 씁니다. HUD에 해골(킬)·시계(생존 시간), 상점 버튼에 `icon_shield`·`icon_speed`, 레벨업 카드에 스킬 아이콘, 랭킹 1~3위에 왕관·메달을 붙였습니다. 그림이 없으면 예전 CSS 모양으로 돌아갑니다.
- 무리 속에서 법사를 잃지 않게 발밑에 노란 고리를 표시합니다.

### 몹 10종 (`mobs.types`)
슬라임 · 박쥐(가장 빠름, 좌우로 흔들며 남) · 늑대 · 버섯(느림) · 고블린 · 해골 · 유령(무리를 통과, 반투명) · 오크 · 골렘(가장 단단함) · 흑기사(빠르고 단단한 후반 정예).
시간에 따라 `spawn.typeWeights` 표대로 섞여 나옵니다. 밀도 밀어내기는 몹 크기(`mass`)를 반영해 큰 몹일수록 넓게 퍼집니다.

### 밸런스 확인 (무적 자동 봇 8.5분)
4종 보스가 모두 제때 등장했고, 레벨업 평균 약 36초 간격, 메테오 약 7초에 한 발, 8분에 몹 52,000마리, 오류 없음.

### 성능 메모
- 새 그림은 몹 하나가 15~31픽셀로 예전(12~20)보다 커서 **GPU가 칠하는 픽셀 수가 약 2배**입니다. CPU 시뮬레이션 비용은 이전과 같은 수준(이 PC 기준 기준 루프의 약 11배)입니다.
- 폰에서 `?bench=60000`이 30fps 아래로 떨어지면 원인은 GPU일 가능성이 큽니다. 그때는 몹 그림만 한 단계 작은 버전(예: 절반 크기로 다시 그린 것)을 쓰거나 `CONFIG.pixel.nativeMax` 를 낮춰 큰 그림을 줄이게 할 수 있습니다.

### 쓰지 않은 그림
`fx_crater`(크레이터는 메테오 모양마다 색이 달라야 해서 코드 도형 유지), `meteor_*_down`(불꽃만 카드 아이콘으로 사용), `icon_hp`, `ui_heart`, `ui_gear`. 체력·설정 아이콘 자리가 생기면 붙이겠습니다.

## 11. 체력과 밸런스 재조정 (2026-11-19)

### 법사 체력
- 한 번 닿으면 죽던 규칙을 **체력 100**으로 바꿨습니다(`player.hp`). 닿은 몹 중 가장 아픈 하나만 피해를 주고, 피해 후 0.8초 무적(깜빡임) + 주변 몹을 밀쳐내 빠져나갈 틈을 만듭니다.
- 4초 동안 안 맞으면 초당 2.5씩 회복. 쉴드는 여전히 피해 1회를 통째로 막습니다.
- 피해: 슬라임 6 · 박쥐 3 · 늑대 5 · 버섯 7 · 고블린 8 · 해골 8 · 유령 5 · 오크 12 · 골렘 15 · 흑기사 14 · 보스 접촉 25 · 드래곤 불덩이 20 · **자기 메테오 50**(대시 중에도 맞음 — 떨어지기 전에 원 밖으로).
- 물약은 체력 물약(+35)으로 바뀌었고, 특수 카드에 **생명력**(최대 체력 +25, 전부 회복, 최대 2번)이 추가됐습니다.
- HUD에 하트·체력 막대, 맞으면 화면 가장자리가 붉게 번쩍, 체력이 깎이면 법사 머리 위에 작은 체력 막대가 보입니다.

`tools/balance.html`(봇이 실제 규칙으로 화면 없이 한 판을 플레이)로 측정했습니다. 봇은 무리를 피해 다니며 마력이 차면 가장 빽빽한 곳을 몹이 올 쪽으로 당겨 조준합니다(실력 0.8, 판마다 다른 시드).

|---|---|---|---|---|
| 평균 생존 | 78초 | 89초 | 98초 | 93초 |
| 박쥐에게 받은 피해(체력 100 중) | **71** | 14 | 5 | 1 |

## 12. 중앙 메테오와 첫 판 안내 (2026-11-19)

**메테오는 누른 순간의 화면 중앙(그때 법사가 서 있던 자리)에 떨어집니다.** 마력이 차면 화면 아무 곳이나 탭하면 됩니다. 떨어질 자리는 누른 순간 고정되고, 법사가 움직여도 바뀌지 않습니다.
- **자기 메테오에 다칩니다(50).** 대시 중이어도 맞으므로, 떨어지기 전에 빨간 원 밖으로 나가야 합니다. 원 바로 바깥(45 이내)으로 빠져나가면 아슬아슬 보너스(마력 +20%)를 받습니다.
- **노리는 플레이**: 탭 → 몹을 끌어모음 → 떨어지기 직전에 대시로 탈출.
- **시전 보호막**: 메테오가 떨어지는 동안(1.2초)에는 몹에게 다치지 않고 몹을 밀쳐내지도 않아서, 몹이 법사 주변으로 모여듭니다. 자기 메테오 피해는 막지 않습니다. (보호막이 없으면 맞을 때 밀쳐내기(120)가 몹을 반경 밖으로 날려 메테오가 빈 땅에 떨어졌습니다.)
- **대시 거리가 메테오 반경을 따라 커집니다.** 반경 120에 대시 140이라 중앙에서 대시 한 번이면 빠져나갑니다. 범위 카드로 반경이 커져도(2장이면 159) 대시도 같은 비율로 늘어(185) 항상 탈출할 수 있습니다. 이게 없으면 범위 카드 2장부터는 중앙에서 탈출이 불가능했습니다(`dash.scaleWithMeteor`).
- 예전 방식(탭한 자리)으로 되돌리려면 `js/config.js` 의 `meteor.target` 을 `'tap'` 으로 바꾸면 됩니다.

봇 측정(6판). 봇은 마력이 차고 대시가 있을 때 탭하고, 제자리에서 몹을 모은 뒤 떨어지기 0.2~0.35초 전에 대시로 빠져나갑니다.

| 설정 | 봇 실력 | 평균 생존 | 킬 | 자기 메테오 피해 |
|---|---|---|---|---|
| 탭한 자리 (이전) | 0.8 | 213초 | 2,115 | - |
| 중앙, 자기 피해 있음, 대시 고정 140 | 0.8 | 168초 | 668 | 판당 83 (사망 5/6) |
| **중앙, 자기 피해 있음, 대시가 반경 따라 커짐 (채택)** | 0.8 | **202초** | 2,315 | 0 |
| 〃 | 0.5 | 233초 | 2,127 | 0 |

봇은 타이밍이 정확해서 자기 메테오에 맞지 않지만, 사람은 탈출이 늦으면 50을 맞습니다. 그 긴장이 이 방식의 재미입니다.

**첫 판 안내**: 안내가 끝나거나 `건너뛰기`를 누를 때까지 게임이 멈춰 있습니다(시간·몹 생성 없음). 안내 상자는 법사 위쪽에 떠서 캐릭터를 가리지 않고, 상자를 누르면 다음 안내로 넘어갑니다.

## 14. 2차 수정 — 메테오 버튼, 배경음악, 난이도 (2026-11-20)

랭킹은 **시즌 3**, 난이도 **normal** 만 등록합니다.

**메테오**
- 평원 탭은 아무 일 없음(이동만). 마력이 차면 메테오 버튼(마력 링 자리 그대로)이나 PC 의 Space 를 누릅니다.
- 낙하 지점은 누른 순간 법사 자리에 고정되고, 법사를 따라가지 않습니다.
- 낙하 시간 = max(1.0초, 반경 ÷ (현재 이동 속도 × 0.85)). 범위를 아무리 키워도 대시 없이 곧장 달리면 빠져나갑니다(`meteor.escapeFactor`).
- 붉은 원 안쪽 테두리가 줄어드는 모습으로 남은 시간을 보여 줍니다.
- 반경 안에 있으면 몹이 가장 적은 쪽으로 연한 화살표가 나옵니다(설정 "탈출 방향 표시").
- 쌍둥이: 첫 발은 누른 자리, 둘째 발은 0.5초 뒤 그때 법사 자리에 떨어집니다.

**배경음악** (`js/music.js`, `audio/README.md`)
- `audio/*.mp3` 가 있으면 파일, 없으면 이 게임용으로 새로 작곡한 내장 음악을 씁니다. 내장 음악은 악보 데이터를 FM풍 합성(오실레이터 2개 변조) + 팀파니·스네어·심벌로 OfflineAudioContext 에 녹음한 것입니다.
- 곡: 타이틀 D장조, 평원 G장조 행진곡, 위기 D단조, 무적의 별 F장조, 징글 3개(메테오 습득·레벨업·게임 오버).
- 반복은 AudioBuffer 로 틈 없이 합니다. mp3 앞뒤 무음은 잘라냅니다.
- 루프 지점을 안 적은 파일은 끝의 페이드아웃을 찾아 잘라내고, 0.5초 크로스페이드로 이어 붙입니다. 지점을 정하려면 `audio.tracks.<이름>.loopStart/loopEnd` 를 적습니다.
- 위기 음악: 보스가 있거나 몹이 2만을 넘으면 2초 크로스페이드로 전환하고, 조건이 풀리고 10초 뒤 되돌아갑니다.
- 무적의 별 동안은 별 음악을 틀고, 끝나면 이전 곡으로 돌아갑니다.
- 경기 중에는 음악을 70%로 낮추고, 폭발 때 0.3초 덕킹합니다.
- 음악·효과음 볼륨은 설정에서 따로 바꾸고 저장됩니다.
- 첫 터치 전에는 재생하지 않고, 앱을 나가면 멈춥니다.
- 메모리: 오디오를 32kHz 로 쓰고, 긴 곡 파일은 2곡까지만 메모리에 둡니다.

## 15. 랭킹 연결 (Supabase)

- 설정: `js/config.js` 맨 위의 `SUPABASE_URL`, `SUPABASE_KEY`(공개 키 `sb_publishable_…`), `RANKING_SEASON`(3). **둘 중 하나라도 비어 있으면 랭킹이 꺼지고 내 기기 최고 기록만 보입니다.** 비밀 키(`sb_secret_`)는 절대 넣지 않습니다.
- `js/ranking.js` 는 fetch 로 RPC 3개만 부릅니다: `submit_score`, `get_top`, `get_my_rank`. 키는 `apikey` 헤더에만 넣습니다(새 공개 키는 JWT 가 아니라 `Authorization: Bearer` 에 넣지 않음).
- 게임오버 때 제출하고 "이번 주 N위"를 보여 줍니다. `too_fast` 는 조용히 넘어가고, `impossible`·`bad_nickname` 은 문구로 알립니다. 게임 도중에는 서버 요청이 없습니다.
- 5초 타임아웃. 실패·오프라인이면 그 판 기록(최고 하나)을 localStorage(`meteor_mage_pending_score`)에 두었다가 다음 실행 때 시작 화면에서 다시 보냅니다.
- 랭킹 화면은 탭마다 불러오고, 같은 탭은 30초 캐시합니다.
- `supabase/schema.sql` 은 예전(자체 서버용) 파일이라 새 함수 모양(`p_period`, `spawn_cap` 표)과 다릅니다. 서버는 따로 준비한 것을 씁니다.
- **스폰 곡선(`spawn.curve`, `curveMul`, 포위 무리 등)이나 시즌을 바꿀 때마다** `tools/spawn_cap.html` 을 열어 SQL 을 다시 만들고 Supabase SQL Editor 에서 실행해야 합니다. (`python tools/serve.py` 후 `http://localhost:8080/tools/spawn_cap.html`)
